# 首页展示模块

## 阶段目标

复现原项目首页的主要观感和信息结构，包括：主视觉、自我介绍、项目展示、GitHub 活跃度、粒子或氛围背景、格言模块，以及首屏之外模块的按需加载思路。

## 任务 1：实现首页信息架构

### 任务说明

先搭骨架，不要一上来就追逐细节动画。首页本质上是多个展示模块按顺序拼接而成，需要先明确模块顺序和数据来源。

### 给 LLM 的提示词

> 请为 Nuxt 3 个人站点设计首页信息架构，要求至少包含：主视觉区、GitHub 活跃度区、精选项目区、格言区，以及一个可选的氛围背景层。请优先实现模块结构和布局关系，让首页信息顺序清晰、滚动节奏自然。所有静态数据优先从统一站点配置读取。

### 交付物

- 首页页面结构
- 模块顺序与容器关系
- 模块级数据来源定义

### 测试方式

- 打开首页，确认信息顺序符合预期。
- 向下滚动页面，观察各模块之间的留白和节奏是否自然。
- 检查页面在移动端是否仍然有清晰的层次。

### 单元测试规划

- 准备创建 `pages/__tests__/home-page-structure.spec.ts`，验证首页关键区块是否渲染。

## 任务 2：实现主视觉 Hero 区

### 任务说明

主视觉是首页的识别核心，需要承载姓名、英文名、角色标签、基础统计、社交入口和向下浏览引导。

### 给 LLM 的提示词

> 请实现首页 Hero 模块，要求包含：中文名或主标题、英文名、副标题或角色标签、若干统计卡片、社交入口、滚动引导。整体风格要适合个人主页，不要过度堆砌装饰。请尽量让内容从统一站点配置读取，并为后续动画预留空间。

### 交付物

- Hero 组件
- 社交入口区
- 统计信息区
- 首页第一屏内容层

### 测试方式

- 检查 Hero 区在桌面端是否居中、在移动端是否易读。
- 检查统计卡片和社交链接是否来自统一配置。
- 点击所有社交链接，确认站内外跳转正确。

### 单元测试规划

- 准备创建 `components/home/__tests__/hero-section.spec.ts`，测试标题、统计卡片和社交入口渲染。

## 任务 3：实现粒子或氛围背景层

### 任务说明

原项目首页有粒子背景，但这类效果很容易拖累性能。Nuxt 版本复现时要明确这是一个首页专属、可降级、客户端执行的视觉增强层。

### 动画技术选型补充

- 最实用的组合通常是：`GSAP + Motion for Vue`。
- 如果需要 3D 背景、空间感粒子或镜头感动效，再引入 `TresJS`。
- 默认建议先用 `Motion for Vue` 处理页面进入、区块浮现、列表错峰等声明式动画，再用 `GSAP` 处理滚动联动、时间轴编排和复杂过渡。
- `TresJS` 不建议作为默认必选项，只有在首页背景明确需要 3D 视觉层时再接入，并保留移动端降级方案。

### 风格方向参考

- 博客风：以低干扰、轻动效为主，适合段落渐入、标题上浮、卡片轻微视差，重点保证阅读稳定性。
- 作品集风：适合加入更明显的滚动编排、项目卡片入场、分屏切换与 hover 反馈，强调展示感。
- 极简科技风：适合使用克制的发光、网格、流体渐变、粒子或轨迹动画，但要优先控制首屏负担和交互遮挡。

### 给 LLM 的提示词

> 请为首页实现一个仅在客户端运行的氛围背景层，可以是粒子背景或近似的轻量动态背景。要求：只在首页启用、不要遮挡正文交互、移动端可以降级、实现方式与 Nuxt 的客户端渲染机制兼容。请优先保证稳定性和性能，不必追求复杂特效。

### 交付物

- 首页背景效果组件
- 客户端专用挂载方式
- 移动端降级策略

### 测试方式

- 打开首页，确认背景存在但不阻挡按钮和链接点击。
- 切换到其他页面，确认背景不会错误残留。
- 在移动端设备或浏览器模拟器中检查效果是否已降级。
- 观察页面滚动和交互时是否出现明显卡顿。

### 单元测试规划

- 动画背景更适合手动测试与性能测试。
- 可准备创建 `tests/visual/home-background-checklist.md`，记录首页背景交互和性能验收项。

## 任务 4：实现 GitHub 活跃度展示区

### 任务说明

原项目首页展示 GitHub 贡献热力图，并链接到 GitHub 主页。Nuxt 版本可以保持同类功能，但需考虑外部资源加载和主题兼容。

### 给 LLM 的提示词

> 请为首页实现 GitHub 活跃度展示区，要求包含：区块标题、可视化展示区域、跳转到 GitHub 主页的入口。请优先考虑外部资源加载的稳定性、暗色主题下的观感、以及小屏幕下的横向溢出处理。

### 交付物

- GitHub 活跃度展示模块
- 对外跳转入口
- 横向溢出与主题兼容处理

### 测试方式

- 检查外部资源能否正常显示。
- 切换亮暗主题，确认展示区域仍然可读。
- 在移动端检查是否出现难以处理的横向滚动问题。
- 点击 GitHub 按钮，确认跳转正确。

### 单元测试规划

- 准备创建 `components/home/__tests__/github-contribution.spec.ts`，测试区块标题与链接入口渲染。

## 任务 5：实现精选项目区

### 任务说明

项目卡片是首页最核心的信息展示之一，原项目的项目数据来自统一配置，并带有分类和标签。Nuxt 复现时也应保持这种配置驱动方式。

### 给 LLM 的提示词

> 请实现首页精选项目区，项目数据全部来自统一站点配置。每张项目卡片至少要展示：项目名、简要描述、技术标签、项目分类、外链入口。分类要有明显视觉区分，但不要做得太花。请确保卡片列表在桌面端和移动端都有合理布局。

### 交付物

- 项目区组件
- 项目卡片组件
- 分类样式映射
- 配置驱动的数据渲染逻辑

### 测试方式

- 修改统一站点配置中的项目数据，确认首页卡片能同步更新。
- 检查项目分类标签是否与配置一致。
- 点击每张卡片中的外链入口，确认目标地址正确。
- 在不同屏幕宽度下观察卡片换行和高度是否自然。

### 单元测试规划

- 准备创建 `components/home/__tests__/featured-projects.spec.ts`，测试卡片数量、分类标签、外链入口和标签渲染。

## 任务 6：实现格言区与首页收尾节奏

### 任务说明

原项目在首页尾部用格言模块收尾。这个模块不复杂，但很适合提炼成通用组件，后续博客页和简历页也能复用。

### 给 LLM 的提示词

> 请实现一个可复用的格言组件，并在首页底部接入。组件要求支持传入一句短文案，视觉上要与卡片体系兼容，适合作为页面结尾收束气氛。请同时考虑这个组件后续可在博客页、简历页、关于页复用。

### 交付物

- 通用格言组件
- 首页格言接入

### 测试方式

- 检查格言组件在首页中的间距与视觉权重是否合适。
- 在另一个页面临时复用该组件，确认不会与当前页面结构强耦合。

### 单元测试规划

- 准备创建 `components/common/__tests__/motto-block.spec.ts`，测试文案渲染与可复用性。

## 任务 7：实现首页首屏外模块的按需加载策略

### 任务说明

原项目对首屏以下模块做了延迟加载，这是很有价值的复现点。Nuxt 版本也应考虑把不影响首屏的展示模块延后加载。

### 给 LLM 的提示词

> 请为首页中首屏以下的非关键模块设计按需加载策略，优先考虑 GitHub 活跃度区、精选项目区或其他不影响首屏的展示模块。要求不改变用户看到的内容结构，但要减少首屏负担。请说明哪些模块适合延迟、为什么适合延迟，以及我应该如何验证优化确实生效。

### 交付物

- 首页按需加载方案
- 适合延迟模块的清单
- 验证优化效果的方法说明

### 测试方式

- 使用浏览器性能面板观察首屏资源加载顺序是否更合理。
- 对比优化前后首页首次可见内容的稳定性。
- 检查延迟模块加载后是否出现闪烁、布局突变或事件失效。

### 单元测试规划

- 这类优化更适合结合手动性能测试和端到端验证。
- 可准备创建 `tests/performance/home-lazy-modules-checklist.md` 作为验收清单。

## 本阶段完成标准

满足以下条件后，再进入博客模块：

1. 首页信息结构完整。
2. 统一配置已经驱动 Hero、项目区等模块。
3. 背景效果不会干扰交互。
4. 首屏外模块已有清晰的加载优化策略。
