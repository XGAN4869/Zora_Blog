# 博客内容系统

## 阶段目标

复现原项目的博客能力，但技术实现切换为更适合 Nuxt 3 的内容方案。建议优先使用 Nuxt Content 或等价的内容管理方式，以实现内容目录驱动的博客系统。

## 任务 1：建立博客内容目录与元信息规范

### 任务说明

原项目通过内容目录和 frontmatter 管理文章标题、日期、描述、标签和阅读时长。Nuxt 版本也要先明确“内容怎么存、元信息长什么样”。

### 给 LLM 的提示词

> 请为这个 Nuxt 3 项目建立博客内容管理方案，优先考虑内容目录驱动的方式。请设计文章文件放置规则、文章元信息规范，以及博客列表页和详情页后续所需的字段。至少要覆盖：标题、日期、摘要、标签、slug、阅读时长。此任务先不要完成页面视觉细节，重点是内容组织方案和数据读取思路。

### 交付物

- 博客内容目录约定
- 文章元信息规范
- 内容读取方案说明

### 测试方式

- 准备两到三篇示例文章内容文件，确认系统可以识别。
- 人工核对文章元信息字段是否足够支撑列表页和详情页。
- 故意缺失某个字段，确认系统如何兜底或给出提示。

### 单元测试规划

- 准备创建 `content/__tests__/post-meta.spec.ts`，用于验证文章元信息完整性与字段默认值策略。

## 任务 2：实现博客列表页

### 任务说明

博客列表页要承担文章聚合、标签筛选和文章入口功能，是内容系统的主页。

### 给 LLM 的提示词

> 请实现博客列表页，要求展示文章标题、摘要、日期、阅读时长、标签，并支持按标签筛选。请优先保证数据来源清晰、筛选交互直观、空状态友好。页面风格应延续站点的统一卡片和主题体系。

### 交付物

- 博客列表页
- 标签筛选交互
- 空状态和无文章提示

### 测试方式

- 确认列表页能正确展示全部文章。
- 点击某个标签后，确认只显示对应文章。
- 清空筛选后，确认文章列表恢复。
- 删除所有文章内容文件后，确认空状态可读、页面不报错。

### 单元测试规划

- 准备创建 `pages/blog/__tests__/blog-list.spec.ts`，测试文章列表渲染、标签筛选和空状态展示。
- 准备创建 `composables/__tests__/use-blog-filter.spec.ts`，测试筛选逻辑是否正确。

## 任务 3：实现博客详情动态页

### 任务说明

详情页需要结合动态路由、内容渲染、页面元信息和文章导航返回。这里既要保证内容能渲染，也要保证路由层行为稳定。

### 给 LLM 的提示词

> 请实现博客详情动态页，要求支持根据文章 slug 渲染正文内容，并展示标题、日期、阅读时长、标签和返回列表页入口。还需要为文章详情设置页面级标题和描述。请优先保证路由清晰、内容渲染稳定、404 场景处理合理。

### 交付物

- 博客详情动态页
- 页面级 SEO 配置
- 返回列表页入口
- 文章不存在时的兜底方案

### 测试方式

- 访问真实存在的文章 slug，确认正文可见。
- 手动访问不存在的 slug，确认有合理兜底而不是空白页。
- 检查浏览器标签标题和描述是否随文章变化。
- 从列表页进入详情页，再返回列表，确认路由体验正常。

### 单元测试规划

- 准备创建 `pages/blog/__tests__/blog-detail.spec.ts`，测试详情元信息展示、返回入口和 404 场景。

## 任务 4：实现正文排版与内容增强

### 任务说明

原项目博客正文具备较完整的 prose 风格，还支持 Mermaid 图表。Nuxt 版本可以继续保留这类能力，但应先明确是“内容增强”而非“页面逻辑”。

### 给 LLM 的提示词

> 请为博客正文建立统一的内容排版体系，要求覆盖：标题层级、段落、列表、引用、图片、链接、代码块区域的视觉基线。同时请规划 Mermaid 图表的支持方式，使内容作者可以在文章中使用图表语法并在页面中正确渲染。优先保证可读性、主题兼容和内容安全性。

### 交付物

- 正文排版规范
- Mermaid 支持方案
- 亮暗主题下的正文视觉一致性

### 测试方式

- 准备一篇包含标题、列表、引用、图片、链接和 Mermaid 图表的文章，逐项验证显示效果。
- 切换亮暗主题，确认正文与图表都可读。
- 检查长代码块或宽图表在移动端是否可处理。

### 单元测试规划

- 准备创建 `components/content/__tests__/mermaid-renderer.spec.ts`，测试 Mermaid 容器在客户端渲染和主题切换时的行为。
- 准备创建 `tests/visual/blog-prose-checklist.md`，记录正文排版视觉验收项。

## 任务 5：实现评论区能力

### 任务说明

原项目接入了 Giscus。Nuxt 版本同样可以采用类似方案，但要考虑客户端注入、主题同步和页面重复挂载问题。

### 给 LLM 的提示词

> 请为博客详情页规划并实现评论区能力，优先考虑 Giscus 这类基于 GitHub Discussion 的方案。要求支持：仅在客户端挂载、与全站亮暗主题同步、在路由切换后不重复堆积挂载实例。请把这部分实现成可独立维护的评论组件。

### 交付物

- 评论组件
- 博客详情页接入
- 主题联动方案

### 测试方式

- 打开博客详情页，确认评论区能正常出现。
- 切换主题，确认评论区样式同步变化。
- 在多篇文章之间来回切换，确认不会出现多个评论实例叠加。

### 单元测试规划

- 准备创建 `components/blog/__tests__/comments-host.spec.ts`，验证评论挂载容器渲染和组件生命周期行为。

## 任务 6：建立博客相关工具函数与衍生数据

### 任务说明

文章标签集合、排序规则、日期格式化、阅读时长等都是高频衍生逻辑，应该沉淀为独立工具层或组合式函数。

### 给 LLM 的提示词

> 请为博客系统整理公共工具层或组合式函数，至少覆盖：文章按日期排序、标签集合提取、日期格式化、阅读时长展示文案整理。要求逻辑独立、便于测试，并让博客列表页和详情页都能复用这些能力。

### 交付物

- 博客公共工具层
- 标签和排序等衍生逻辑
- 列表页与详情页共享能力

### 测试方式

- 准备多篇日期不同、标签不同的文章，确认排序和标签汇总正确。
- 检查日期展示格式是否统一。
- 检查阅读时长文案是否稳定且不会出现空值异常。

### 单元测试规划

- 准备创建 `shared/blog/__tests__/blog-utils.spec.ts`，测试排序、标签提取、日期格式化和阅读时长处理。

## 本阶段完成标准

满足以下条件后，再进入简历与关于页：

1. 文章能从内容目录驱动显示。
2. 列表页和详情页均可用。
3. 标签筛选、正文排版、评论区和图表支持都有清晰落点。
4. 博客相关衍生逻辑已有独立测试规划。
