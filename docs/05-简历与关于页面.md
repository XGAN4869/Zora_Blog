# 简历与关于页面

## 阶段目标

复现原项目的个人信息页能力，包括：在线简历、关于页、扩展占位页，并把其中复用度高的数据沉淀为统一配置或独立数据模块。

## 任务 1：实现在线简历页的信息结构

### 任务说明

原项目的简历页并不是简单静态文本，而是带版本切换、模块化内容和 GitHub 展示的复合页面。Nuxt 版本也应保留这种“内容结构清晰、可演进”的特点。

### 给 LLM 的提示词

> 请为 Nuxt 3 个人站点实现在线简历页，要求页面至少包含：简历头部信息、个人总结、教育背景、技能、项目经历、经历占位区域，以及页面底部可复用的格言模块。简历内容请设计成结构化数据驱动，而不是直接把内容硬编码在页面模板里。

### 交付物

- 简历页基础结构
- 简历数据模型
- 模块化展示区块

### 测试方式

- 打开简历页，确认主要区块顺序合理。
- 修改简历数据中的一项内容，确认页面能同步反映。
- 在移动端查看，确认模块没有难以阅读的挤压现象。

### 单元测试规划

- 准备创建 `pages/resume/__tests__/resume-page.spec.ts`，测试主要区块是否渲染。
- 准备创建 `shared/resume/__tests__/resume-data.spec.ts`，测试简历数据结构是否完整。

## 任务 2：实现简历版本切换能力

### 任务说明

原项目简历页的一个亮点是支持不同版本切换，例如最新版本和历史版本。这个能力适合拆为“左侧时间线或版本列表 + 右侧内容区”的结构。

### 给 LLM 的提示词

> 请为在线简历页增加版本切换能力，要求支持至少两份简历版本数据，并通过清晰的交互让用户切换查看。建议采用时间线、版本列表或类似结构。请优先保证数据结构清晰、切换流畅、移动端体验可接受。

### 交付物

- 简历版本数据结构
- 版本切换交互
- 当前版本内容展示区

### 测试方式

- 在简历页切换不同版本，确认内容区域同步变化。
- 反复切换多次，确认没有状态错乱。
- 在移动端检查版本列表是否仍然易于操作。

### 单元测试规划

- 准备创建 `components/resume/__tests__/resume-version-switcher.spec.ts`，测试版本切换逻辑与当前版本渲染。

## 任务 3：在简历页复用 GitHub 活跃度与格言组件

### 任务说明

原项目在简历页底部复用了 GitHub 活跃度模块和格言组件，这是一个很好的“组件可复用性”验证点。

### 给 LLM 的提示词

> 请在不复制实现逻辑的前提下，把首页已经实现的 GitHub 活跃度模块和格言组件复用到简历页底部。请重点保证组件职责清晰、跨页面复用简单，不要为了适配当前页面再做一套重复组件。

### 交付物

- 简历页中的复用模块接入
- 组件复用方案确认

### 测试方式

- 检查首页与简历页显示的是同一套组件能力，而不是复制品。
- 修改复用组件的公共配置后，确认两个页面都能同步受益。

### 单元测试规划

- 可沿用已有组件测试文件，不需要额外重复写同类测试。
- 如有必要，准备创建 `pages/resume/__tests__/resume-shared-sections.spec.ts` 验证复用模块出现。

## 任务 4：实现关于页

### 任务说明

关于页承担的是“更像个人介绍卡”的角色，通常包含头像、技能栈、工具平台、教育信息和联系方式。

### 给 LLM 的提示词

> 请实现关于页，要求包含：头像、英文名或主展示名、个人定位、核心技能栈、工具与平台、教育信息、联系方式以及页尾格言。页面应延续站点统一风格，并尽量使用统一配置或结构化数据驱动，而不是在模板中散落静态文案。

### 交付物

- 关于页主体结构
- 技能与工具分组展示
- 联系方式区
- 统一配置驱动的数据接入

### 测试方式

- 检查头像、名称、联系方式是否正确显示。
- 点击每个联系方式入口，确认跳转或唤起行为符合预期。
- 在桌面和移动端检查分组区块是否整齐。

### 单元测试规划

- 准备创建 `pages/about/__tests__/about-page.spec.ts`，测试头像、技能分组和联系方式渲染。

## 任务 5：实现足迹页占位版本

### 任务说明

原项目的足迹页目前是一个“Coming Soon”型页面。这个页面不复杂，但它能验证扩展页的路由挂载和统一视觉。

### 给 LLM 的提示词

> 请实现一个足迹页的占位版本，要求具备：页面标题、简短说明、明显但克制的占位提示，并保持与全站卡片和主题体系一致。这个页面暂时不做真实地图功能，只作为未来扩展入口。

### 交付物

- 足迹页占位页面
- 与全站一致的视觉壳子

### 测试方式

- 访问足迹页，确认占位内容清晰可见。
- 检查该页面在亮暗主题下都可读。
- 验证其路由能被导航或直接地址访问打开。

### 单元测试规划

- 准备创建 `pages/footprint/__tests__/footprint-placeholder.spec.ts`，测试占位标题和说明文本渲染。

## 任务 6：整理个人资料数据的复用边界

### 任务说明

首页、简历页、关于页之间会共享头像、姓名、社交账号、项目经历等数据。此时需要回头梳理哪些数据该进统一配置，哪些数据该进简历专属模块，避免后续越来越乱。

### 给 LLM 的提示词

> 请帮我梳理这个 Nuxt 3 个人站点中的个人资料数据边界，明确哪些数据应该保留在全局站点配置中，哪些数据应该抽离到简历专属数据模块，哪些数据应该属于关于页专属展示配置。请根据当前项目已有实现做一次结构整理，但不要改变页面外观目标。

### 交付物

- 数据职责边界说明
- 更清晰的数据组织方式

### 测试方式

- 逐项核对首页、关于页、简历页使用的数据来源，确认没有互相挪用或重复定义。
- 修改一个共享字段，例如邮箱或 GitHub 用户名，确认多个页面可同步更新。

### 单元测试规划

- 准备创建 `shared/profile/__tests__/profile-data-boundary.spec.ts`，验证关键共享字段存在且来源稳定。

## 本阶段完成标准

满足以下条件后，再进入最终优化与验收：

1. 简历页内容完整且支持版本切换。
2. 关于页和足迹页均可访问。
3. 多页面之间的共享数据边界已理顺。
4. 复用组件而不是复制组件的思路已经落实。
