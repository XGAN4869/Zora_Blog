# 项目初始化与目录规划

## 阶段目标

先搭建一个稳定的 Nuxt 3 项目骨架，并为后续页面、内容系统、测试体系和性能优化留出清晰结构。

## 任务 1：初始化 Nuxt 3 + Vue 3 + TypeScript + Windi CSS 项目

### 任务说明

先完成项目脚手架、基础依赖、开发环境、样式方案和测试工具的选型与接入。这里的重点不是做页面，而是先把“可持续开发”的地基搭好。

### 给 LLM 的提示词

> 请帮我初始化一个 Nuxt 3 + Vue 3 + TypeScript + Windi CSS 项目，并补齐后续开发会用到的基础工程能力。要求包含：基础目录、Windi CSS 接入、ESLint、类型检查、基础单元测试工具、适合后续内容站开发的配置。先不要实现任何业务页面，只完成项目初始化和工程底座，并告诉我每一项配置的作用。

### 交付物

- Nuxt 项目基础结构
- Windi CSS 已接入且可用
- TypeScript 配置可正常工作
- ESLint 与基础测试工具已就位
- 后续开发所需的基础别名、静态资源目录、组件目录已建立

### 测试方式

- 启动开发环境，确认首页能正常打开且没有明显报错。
- 执行生产构建，确认项目可成功打包。
- 执行类型检查，确认没有基础类型错误。
- 执行 ESLint，确认基础模板文件通过静态检查。
- 在页面中临时放置一两个 Windi CSS 原子类进行肉眼验证，确认样式生效。

### 单元测试规划

- 准备创建 `tests/setup` 相关测试初始化文件，用于后续统一管理测试环境。
- 准备创建 `app/__tests__/app-shell.spec.ts`，用于后续验证最基本的应用壳子是否能正确挂载。

## 任务 2：规划目录结构与命名约定

### 任务说明

这个项目是典型的内容驱动型个人站点，目录混乱会极大提高后续返工成本。需要尽早统一页面、组件、内容、配置和测试文件的职责边界。

### 给 LLM 的提示词

> 请基于 Nuxt 3 内容站项目，为我规划清晰的目录结构与命名规则。至少要覆盖：页面路由、布局、通用组件、首页组件、博客组件、内容目录、配置目录、组合式函数目录、类型定义目录、测试目录。请直接落目录，不要实现业务逻辑，并说明每个目录后续承担什么职责。

### 交付物

- 页面层目录
- 布局层目录
- 首页、博客、通用组件目录
- 内容目录
- 公共配置与类型目录
- 测试目录

### 测试方式

- 由你手动检查目录是否能让人一眼看出职责边界。
- 让 LLM 列出每个目录的用途，确认没有职责重叠。
- 如果已经启用自动导入，确认目录位置不会引发命名冲突。

### 单元测试规划

- 准备创建 `tests/architecture/directory-conventions.spec.ts`，用于后续校验关键目录和关键配置文件是否存在。

## 任务 3：建立站点数据中心与公共类型

### 任务说明

原项目里很多页面都依赖一份统一配置，例如站点标题、导航、社交链接、项目列表、项目分类等。Nuxt 复现时也应该尽量保持这种“单一数据源”。

### 给 LLM 的提示词

> 请为这个 Nuxt 3 个人站点建立一个统一的站点配置层，集中管理站点名称、标题、描述、导航、社交链接、项目列表、项目分类、头像地址和联系方式，并为这些数据补齐 TypeScript 类型。页面暂时不必完全实现，但后续首页、页脚、关于页、简历页都要能复用这份配置。

### 交付物

- 统一的站点配置文件
- 与站点配置匹配的类型定义
- 后续页面可复用的数据出口

### 测试方式

- 手动检查配置项是否足够覆盖首页、导航、页脚、项目卡片、关于页和简历页。
- 让 LLM 输出配置字段清单，确认不会出现页面各自维护一份重复数据的问题。
- 故意修改一条配置数据，再观察后续页面是否可以统一消费这份数据。

### 单元测试规划

- 准备创建 `shared/config/__tests__/site-config.spec.ts`，用于验证关键配置字段完整性、项目分类映射完整性和 URL 字段格式合理性。

## 任务 4：建立基础路由占位页面

### 任务说明

先把主要路由壳子建出来，后面每个页面只需要往对应目录填内容，而不必重复处理路由接入问题。

### 给 LLM 的提示词

> 请先为这个 Nuxt 3 项目建立基础页面路由，占位即可，但必须覆盖：首页、博客列表页、博客详情动态页、简历页、关于页、足迹页。要求路由结构清晰，页面标题和基础文案可以先使用占位内容，但每个页面都要能独立访问。

### 交付物

- 首页路由
- 博客列表路由
- 博客详情动态路由
- 简历页路由
- 关于页路由
- 足迹页路由

### 测试方式

- 逐一访问各个页面地址，确认没有 404。
- 手动刷新动态路由页面，确认 Nuxt 路由和构建行为正常。
- 检查页面切换时控制台是否存在 hydration 或路由警告。

### 单元测试规划

- 准备创建 `pages/__tests__/route-existence.spec.ts`，用于验证关键页面组件文件存在。
- 如果后续接入端到端测试，可准备创建 `tests/e2e/basic-routing.spec.ts`，验证关键页面能正常打开。

## 任务 5：建立基础质量门禁

### 任务说明

如果一开始不把“怎么判断当前步骤完成”说清楚，LLM 很容易在后续阶段边实现边破坏前面的工作。

### 给 LLM 的提示词

> 请为这个 Nuxt 3 项目建立最小可用的质量门禁，至少覆盖：开发可启动、生产可构建、类型检查可通过、ESLint 可通过、单元测试命令可执行。请只完成工程质量门禁相关工作，并告诉我后续每个阶段都应该重复执行哪些验证动作。

### 交付物

- 可重复执行的开发检查流程
- 构建检查流程
- 静态检查流程
- 单元测试入口

### 测试方式

- 连续执行开发启动、构建、类型检查、ESLint、测试入口，确认都可运行。
- 故意制造一个简单类型错误，确认类型检查确实能拦截问题。
- 故意制造一个简单语法风格问题，确认 ESLint 能拦截问题。

### 单元测试规划

- 准备创建 `tests/quality/quality-gate.spec.ts`，用于后续补充对关键公共模块的最低限度健康检查。

## 本阶段完成标准

满足以下条件后，再进入下一份文档：

1. 项目已经是 Nuxt 3 + Vue 3 + TypeScript + Windi CSS。
2. 关键路由壳子已存在。
3. 站点配置中心已建立。
4. 类型检查、静态检查、构建检查有明确入口。
5. 后续页面开发不会因为基础目录和工具链问题反复返工。
