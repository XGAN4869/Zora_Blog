# 性能优化与最终验收

## 阶段目标

把前面完成的 Nuxt 3 个人站点收口到“可上线”的状态。这个阶段既要补性能策略，也要把测试和验收体系明确下来，避免项目看起来完成了但实际上不稳定。

## 任务 1：梳理首屏与客户端组件边界

### 任务说明

原项目中有几个很典型的性能点：首屏以下模块延迟加载、粒子背景仅客户端运行、外部资源预连接、图片处理、评论区与图表的客户端挂载。Nuxt 版本也要把这些边界梳理清楚。

### 给 LLM 的提示词

> 请基于当前 Nuxt 3 项目，梳理哪些模块应该留在首屏关键路径，哪些模块适合延迟加载，哪些模块必须客户端运行。重点关注：首页背景效果、GitHub 活跃度区、评论区、图表组件、首屏外展示模块。请在不改变页面功能的前提下优化资源加载边界，并告诉我如何验证优化确实生效。

### 交付物

- 首屏关键路径说明
- 客户端专属模块清单
- 按需加载优化方案

### 测试方式

- 用浏览器性能工具查看首屏请求与脚本加载顺序。
- 对比优化前后首页初次可见内容的稳定性。
- 检查客户端组件在服务端渲染阶段不会引发报错。

### 单元测试规划

- 这类优化更适合手动性能测试与端到端验证。
- 可准备创建 `tests/performance/client-boundary-checklist.md`，记录各组件的运行边界。

## 任务 2：补充外部资源与图片优化策略

### 任务说明

原项目对外部图表资源做了预连接，也对图片尺寸与加载行为进行了关注。Nuxt 版本不一定一模一样实现，但需要保留同层级优化意识。

### 给 LLM 的提示词

> 请检查当前 Nuxt 3 项目中的外部资源与图片使用方式，并做一轮基础优化。重点关注：是否需要对关键外部资源做预连接、头像和文章图片是否有明确尺寸策略、首屏图片是否有清晰加载优先级、正文内图片和宽内容在移动端是否可控。请优先给出稳妥且容易验证的优化，而不是过度工程化。

### 交付物

- 外部资源优化策略
- 图片使用规范
- 移动端宽内容兜底方案

### 测试方式

- 打开首页与博客详情页，检查关键图片是否稳定显示。
- 在网络较慢的环境中观察首屏内容和图片出现顺序。
- 检查移动端长图、宽图、宽内容是否破版。

### 单元测试规划

- 图片与外部资源更适合手动验收。
- 可准备创建 `tests/visual/media-behavior-checklist.md` 作为验收清单。

## 任务 3：为公共逻辑补齐单元测试计划

### 任务说明

不是每个界面模块都适合用单元测试覆盖，但公共逻辑、数据处理、状态管理和核心交互应该有明确测试落点。

### 给 LLM 的提示词

> 请基于当前 Nuxt 3 项目，帮我整理一份单元测试落点清单。重点挑选真正值得测的逻辑，包括：站点配置、主题状态、博客筛选逻辑、日期格式化、标签汇总、简历版本切换等。请按模块列出建议新增的测试文件路径，以及每个测试文件要覆盖哪些行为，不要输出测试代码。

### 交付物

- 单元测试清单
- 每个测试文件对应的覆盖目标

### 测试方式

- 检查测试清单是否覆盖了“容易出错的逻辑”而不是只覆盖静态文案。
- 让 LLM 再复述一遍每个测试文件的价值，确认没有低价值重复测试。

### 单元测试规划

- 本任务本身就是单元测试规划任务。
- 产出应覆盖此前所有阶段已经提到的测试文件规划，并做一次统一汇总。

## 任务 4：规划端到端验收场景

### 任务说明

对于主题切换、导航跳转、博客筛选、评论区挂载、动态路由等能力，端到端测试比单元测试更贴近真实用户行为。

### 给 LLM 的提示词

> 请为这个 Nuxt 3 个人站点设计一组最小但高价值的端到端验收场景，要求覆盖：首页打开、导航跳转、主题切换、博客筛选、博客详情访问、简历版本切换、关于页联系方式可用、足迹页可访问。请说明每个场景应该验证什么，以及建议把测试文件放在哪里。不要输出端到端测试代码。

### 交付物

- 端到端场景清单
- 每个场景的验证目标
- 测试文件规划

### 测试方式

- 把这些场景当作人工回归清单手动走一遍。
- 如果后续接入 Playwright 或等价工具，再将清单转成自动化测试。

### 单元测试规划

- 本任务属于端到端测试规划，不是单元测试。
- 可准备创建 `tests/e2e` 目录下的多个场景文件，并按页面功能拆分。

## 任务 5：执行最终回归验收

### 任务说明

这是项目能否结束的关键一步。需要把“页面像不像”升级为“功能是否稳定、配置是否清晰、测试路径是否明确、性能是否可接受”。

### 给 LLM 的提示词

> 请根据当前已经完成的 Nuxt 3 个人站点，输出一份最终回归验收清单。清单至少覆盖：页面访问、响应式布局、主题一致性、外链可用性、博客内容渲染、评论区、动态图表、性能优化点、SEO 信息、构建稳定性。请按高优先级到低优先级排序，方便我上线前逐项核对。

### 交付物

- 最终回归清单
- 上线前高优先级检查项

### 测试方式

- 按清单逐项手动回归。
- 对每项标注“通过 / 不通过 / 待确认”。
- 对不通过项重新回到对应阶段文档修复。

### 单元测试规划

- 本任务以人工验收为主。
- 可准备创建 `docs/final-qa-checklist.md` 或 `tests/qa/final-regression-checklist.md` 作为最终验收记录。

## 项目上线前必须确认的事项

1. 开发环境、构建、类型检查、ESLint、单元测试入口都可执行。
2. 首页、博客、简历、关于、足迹五类页面都能独立访问。
3. 主题切换、导航跳转、评论区、动态图表等关键交互不报错。
4. 内容目录中的文章能稳定生成列表和详情。
5. 统一站点配置没有出现多处重复维护。
6. 页面在移动端和桌面端都具备可接受的布局表现。
7. 已经有一份可以反复执行的最终回归清单。

## 这份文档的正确使用方式

不要把这一阶段当作“可有可无的收尾”。如果缺少这一步，前面所有页面都可能只是看起来完成，但并不具备稳定上线的把握。最稳妥的节奏是：每完成一个优化点，就立刻回归一次关键路径。
