# 全局框架与主题系统

## 阶段目标

复现原项目的全局外壳能力，包括：统一布局、导航栏、页脚、主题切换、基础 SEO、全局样式变量和页面层级结构。

## 任务 1：实现默认布局与页面骨架

### 任务说明

原项目有稳定的全局壳子：顶部导航、主体区域、底部页脚、全站样式和元信息。Nuxt 版本也要先建立默认布局，让后续所有页面挂在统一框架上。

### 给 LLM 的提示词

> 请为这个 Nuxt 3 项目实现默认布局，要求包含：固定或半固定顶部导航区域、主内容区域、页脚区域、基础页面容器宽度控制，以及适合个人站点的整体层级结构。先聚焦全局布局，不要展开首页或博客业务内容。实现后请说明布局文件、公共组件和页面容器分别放在哪里。

### 交付物

- 默认布局文件
- 公共页面容器规范
- 主体内容区和页脚区的层级关系

### 测试方式

- 随机打开多个页面，确认导航和页脚都能复用出现。
- 检查页面切换后布局是否稳定，没有高度跳变或遮挡。
- 在移动端和桌面端分别验证内容容器宽度是否合理。

### 单元测试规划

- 准备创建 `layouts/__tests__/default-layout.spec.ts`，验证布局基础区域存在。
- 准备创建 `components/layout/__tests__/page-shell.spec.ts`，验证主内容区域是否正确渲染插槽。

## 任务 2：实现导航栏与当前路由高亮

### 任务说明

导航是整个站点最常用的公共组件，需要兼顾桌面端、移动端和当前路由状态识别。

### 给 LLM 的提示词

> 请基于统一站点配置实现导航栏组件，要求支持：站点名称展示、导航菜单渲染、当前路由高亮、移动端菜单展开与收起、与主题切换按钮共存。请优先保证响应式体验和组件可复用性，不要实现与当前任务无关的复杂动画。

### 交付物

- 导航栏组件
- 移动端菜单交互
- 当前路由高亮逻辑

### 测试方式

- 在所有主页面间切换，确认当前导航项高亮准确。
- 缩小浏览器宽度，确认移动端菜单能正常展开和关闭。
- 点击移动端菜单项后，确认菜单自动收起。

### 单元测试规划

- 准备创建 `components/layout/__tests__/navbar.spec.ts`，测试导航项渲染、当前路由高亮、移动端展开收起行为。

## 任务 3：实现页脚与外部链接区

### 任务说明

原项目页脚既是补充导航，也是对外链接和联系方式的承载区。这个模块适合尽早完成，因为很多公共数据都要在这里验证。

### 给 LLM 的提示词

> 请实现一个适合个人站点的页脚组件，内容来源于统一站点配置。页脚至少要展示：站点名称或简介、站内导航、对外链接、联系方式。要求结构清晰、信息密度适中、移动端也能良好展示。

### 交付物

- 页脚组件
- 外部链接区
- 联系方式展示区

### 测试方式

- 检查页脚是否能正确消费统一站点配置。
- 点击所有外部链接，确认跳转目标和新窗口行为符合预期。
- 验证页脚在内容较少的页面中仍然处于合理位置。

### 单元测试规划

- 准备创建 `components/layout/__tests__/footer.spec.ts`，验证链接渲染、联系信息渲染和配置驱动行为。

## 任务 4：实现主题系统与亮暗模式切换

### 任务说明

原项目使用亮暗主题切换，并让多个模块跟着主题联动。Nuxt 版本应尽早统一设计 token 和主题状态来源。

### 给 LLM 的提示词

> 请为这个 Nuxt 3 项目设计亮色与暗色两套主题系统，并实现主题切换能力。要求包含：全局主题状态、主题切换按钮、基础色板变量、卡片背景、文字颜色、边框颜色与强调色。请优先考虑后续首页卡片、博客正文、评论区和图表区域的主题一致性。

### 交付物

- 主题状态管理方案
- 主题切换按钮
- 全局颜色变量与基础样式层

### 测试方式

- 手动切换主题，确认导航、页脚、卡片、正文颜色同步变化。
- 刷新页面后，确认主题状态按预期保留。
- 检查主题切换是否引发明显闪烁或 hydration 警告。

### 单元测试规划

- 准备创建 `components/common/__tests__/theme-toggle.spec.ts`，测试切换行为与可访问性。
- 准备创建 `composables/__tests__/use-theme.spec.ts`，测试主题状态读写逻辑。

## 任务 5：实现全局 SEO 与站点级元信息

### 任务说明

原项目在全局层面统一维护标题、描述、Open Graph 等信息。Nuxt 版本应把这部分能力放在布局或应用入口层集中处理。

### 给 LLM 的提示词

> 请基于统一站点配置，为 Nuxt 3 项目实现全局 SEO 元信息能力。要求至少覆盖：默认标题、标题模板、站点描述、站点基础 URL、Open Graph 基础信息、语言信息。请说明哪些内容适合放在全局层，哪些内容应留给具体页面覆盖。

### 交付物

- 全局 SEO 配置
- 页面级 SEO 覆盖策略

### 测试方式

- 打开首页和其他页面，检查浏览器标签标题是否正确。
- 在页面源码或调试工具中检查 meta 信息是否已注入。
- 手动切换到博客详情页，确认页面级标题能覆盖全局默认标题。

### 单元测试规划

- 准备创建 `tests/seo/seo-config.spec.ts`，验证默认标题模板、站点描述和基础 URL 配置是否存在。

## 任务 6：建立全局样式基线

### 任务说明

除了 Windi CSS 原子类，还需要明确全局背景色、文字色、正文排版、滚动条、过渡、内容区宽度等基线样式，否则页面会越来越散。

### 给 LLM 的提示词

> 请为这个 Nuxt 3 项目建立全局样式基线，要求结合 Windi CSS 和少量全局样式变量，统一处理：页面背景、文字颜色、正文排版、卡片边框、基础过渡、滚动条样式、内容最大宽度。不要写业务页面，只先把全局视觉基线整理好。

### 交付物

- 全局样式入口
- 基础视觉变量
- 内容排版基线

### 测试方式

- 打开所有已存在页面，确认视觉基线一致。
- 检查浏览器缩放、不同分辨率下的页面容器是否依然稳定。
- 用后续页面临时放几个卡片块，确认背景、边框、阴影和文字层次合理。

### 单元测试规划

- 全局样式通常不适合做传统单元测试。
- 可准备创建 `tests/visual/theme-baseline-checklist.md`，作为视觉验收清单使用。

## 本阶段完成标准

满足以下条件后，再进入首页模块：

1. 所有主要页面都挂在统一布局下。
2. 导航、页脚、主题切换都已成型。
3. 全局 SEO 和全局样式基线已建立。
4. 后续页面只需填充内容，不必重复处理公共壳子。
